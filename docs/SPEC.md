# FuSa Trace — 기능안전 추적성·산출물 관리 툴 사양서

> 이 문서는 무엇을 만들지 정합니다. 문서별로 어떻게 읽는지는 `docs/FORMATS.md`에 있습니다.
> 화면 시안(참고용, 가상 데이터): claude.ai 아티팩트 "기능안전 추적성 툴 시안"
> https://claude.ai/artifact/3FURaYLCS3FPNCYCxYg3ca

## 1. 목적

세이프티 매니저가 한 프로젝트(차종 × 제어기)의 기능안전 산출물을 **한눈에** 보도록 합니다.

1. **추적성**: FSR → TSR → (FMEA 근거) → SSR/HSR → 시험까지, 문서에 적힌 연결이 끊긴 곳이 없는지
2. **산출물 작성 현황과 일정**: DIA에 정의된 산출물별 담당, 계획·실적 일정, 작성 여부
3. **출력**: 산출물 작성 리스트를 엑셀로 출력

### 툴의 원칙

- 문서의 원본은 엑셀·워드 파일입니다. 툴은 **읽기만** 하고, 문서 내용을 고치지 않습니다.
- 연결은 문서에 **적혀 있는 참조**만 사용합니다. 내용을 보고 추측해서 연결하지 않습니다.
- 못 읽은 부분은 숨기지 않고 **"못 읽었음"으로 보여 줍니다.** 틀린 결과를 조용히 보여 주는 것보다 낫습니다.

## 2. 범위

### 1단계에 포함

- 설치형 Windows 앱(오프라인, 개인용)
- 문서 넣기: DIA, FSR, TSC, FMEA, SRS, Verification Report(작성 여부만)
- 추적성 화면: 시스템 / 소프트웨어 / 하드웨어 탭, 연결 지도 + 목록
- 산출물 일정 화면(DIA 기준)
- ID 대응표(애매한 연결을 사람이 한 번 고르고 기억)
- 엑셀 출력: 산출물 작성 리스트, 담당자별 요약, 추적성 누락 목록

### 1단계에서 하지 않는 것 (나중)

- 코드비머 연동, 여러 명이 데이터 공유
- 문서 내용 편집, 문서 작성 기능
- Verification Report(동료검토) 체크리스트 내용 읽기 — **작성 여부만** 봄
- SW 유닛·통합 단위 추적, 코드 추적
- 원본 파일에 결과를 다시 써 넣기

### 아직 문서가 없는 것 (자리만 둠)

- SSR 문서(SRS), SW 요구사항 시험 명세, HSR, FMEDA: 화면에 칸은 두고 "문서 미등록"으로 표시. 문서가 생기면 넣는 즉시 연결되도록 읽기 규칙/칸 지정 기능을 갖춤.

## 3. 실행 환경과 기술

| 항목 | 결정 |
|---|---|
| 대상 PC | 회사 Windows 10/11 PC, 관리자 권한 없음, 사내 보안 프로그램 있음 |
| 앱 형태 | Electron 설치형 exe (NSIS, **사용자 단위 설치** — 관리자 권한 불필요) |
| 언어 | TypeScript, 화면은 React + Vite (Claude Code가 더 나은 선택이 있으면 제안 후 결정) |
| 엑셀 읽기 | SheetJS(xlsx) — .xlsx와 .xls 모두 읽기 |
| 워드 읽기 | .docx를 zip으로 열어 `word/document.xml`의 표·제목을 직접 파싱 (병합 셀 처리 필요). .doc은 미지원 안내 |
| 엑셀 쓰기 | ExcelJS (서식, 색, 필터, 틀 고정) |
| 저장 | 프로젝트마다 JSON 파일 1개 (`%APPDATA%/FuSaTrace/projects/<id>.json`). 저장은 임시 파일 → 교체 방식으로 깨짐 방지. 네이티브 모듈 없이 가기 위함 |
| 네트워크 | **실행 중 외부 통신 없음.** 자동 업데이트·원격 폰트·통계 수집 모두 금지. 폰트는 앱에 포함 |
| 빌드 | GitHub Actions (windows-latest)에서 빌드·테스트 → 설치 파일을 Actions 아티팩트 / Release로 배포 |
| 코드 서명 | 없음 (서명 없는 exe가 회사 PC에서 실행되는지 0단계에서 확인) |

### 보안·기밀

- 저장소는 **퍼블릭**(2026-11-10 변경, `docs/DECISIONS.md` 참고). 그래서 실제 회사 문서는 물론 고객사·제품·회사 이름, 실제 ID도 커밋하지 않음 (자리 표시나 가짜 값 사용).
- 테스트용 문서는 **가짜 데이터로 생성**하되, 실제 문서의 양식 특이점을 그대로 재현 (FORMATS.md §9).
- 사용자는 **보안(DRM) 해제한 파일**을 넣음. DRM 파일이 들어오면 읽지 말고 "보안 해제 후 넣어 주세요" 안내 (판별법: FORMATS.md §1).

## 4. 관리 대상과 연결 구조

```
                    [시스템]                         [소프트웨어]                 [하드웨어]
SG ─▶ FSR ─▶ TSR ──┬─(근거)─ FMEA 고장원인      TSR(S/W) ─▶ SSR ─▶ SW 시험   TSR(H/W) ─▶ HSR ─▶ FMEDA
                   │
                   └ 할당(Allocation)에 따라 S/W 탭, H/W 탭으로 나뉨
```

| 항목 | 정의하는 문서 | 위 단계를 가리키는 칸 |
|---|---|---|
| SG, Safe State | FSR 엑셀 | — |
| FSR | FSR 엑셀 | SG (시트 이름 / FSR 표의 SG 칸) |
| TSR | TSC 워드 | Ref ID (FSR ID) |
| FMEA 고장원인 | FMEA 엑셀 | TSR ID 열 |
| SSR | SRS 워드 | Functional Safety Related (TSR ID) |
| SW 시험 케이스 | (양식 미정) | SSR ID — 문서 생기면 칸 지정 |
| HSR | (양식 미정) | TSR ID — 문서 생기면 칸 지정 |
| 산출물(일정) | DIA 엑셀 | — |
| Verification Report | 파일 존재로만 판단 | — |

## 5. 데이터 모델 (프로젝트 JSON 안의 구성)

필드 이름은 예시이며, Claude Code가 구현하며 다듬어도 됩니다.

**Project**: id, 이름(차종·제어기), 생성일, 오늘 기준일(기본: 실제 오늘)

**SourceDoc** (넣은 문서 1개 = 1 레코드, 버전마다 따로 보관)
- 종류(DIA / FSR / TSC / FMEA / SRS / VR / 기타), 원래 파일명, 정규화 파일명(§FORMATS 8), 문서 안 버전(있으면), 넣은 시각, 파일 해시
- 읽기 결과: 읽은 항목 수, 건너뛴 행과 이유, 경고 목록
- 활성 여부(같은 종류·같은 정규화 이름 중 최신만 활성)

**Item** (추적 대상 1개)
- 종류(SG / SS / FSR / TSR / FMEA_CAUSE / SSR / SWTEST / HSR)
- 적힌 ID 그대로(rawId), 정규화 ID, 제목/요약, ASIL, 할당(HW / SW / BOTH / 외부), 요소(Element), 상태값(문서에 적힌 그대로 + 정규화), 출처 문서
- FSR 전용: 구분(자체 / 타 ECU로부터 / 타 ECU에 요구)
- 중복 표시: 같은 문서 안에 같은 rawId가 여러 번이면 각각 보존하고 `중복 #1, #2`로 구분

**Link** (아래 항목 → 위 항목)
- 출발 항목, **적힌 참조 문자열 그대로**, 해석 결과(대상 항목 또는 없음), 해석 방식(정확 / 정규화 / 끝번호 / 별칭 / 애매 / 없음)

**Alias** (사람이 고른 연결 기억): 문서 종류 + 적힌 참조 문자열 → 대상 항목의 정규화 ID. 문서를 새 버전으로 넣어도 유지.

**Deliverable** (DIA에서 온 산출물 1줄; 한 DIA 행에 파일이 여러 개면 여러 줄)
- DIA 행 번호(No.), Part-clause, 산출물 이름(Work product), 문서 라벨(FMEA, DFA, TSC VR 등), 예상 파일명(Actual work product name 한 줄), 정규화 예상 파일명
- 계획 시작/종료, 실적 시작/종료, 담당(팀, 사람 — 여러 명 가능), 메모(파일명이 아닌 글: "FMEDA 대체" 등)
- VR 여부, 연결된 SourceDoc, VR 작성 수동 체크값(사람이 바꾼 경우)
- 날짜 경고(형식 오류, 종료 < 시작)

**Settings**: 칸 이름 동의어 사전, 사용자가 지정한 읽기 규칙(처음 보는 양식용), 오늘 기준일 덮어쓰기

## 6. 문서 넣기 (공통 흐름)

1. 파일을 끌어다 놓거나 선택 (여러 개 한 번에 가능)
2. DRM 검사 → 걸렸으면 안내 후 중단
3. **문서 종류 자동 판별** (FORMATS.md §2). 판별 실패 시 사용자가 종류 선택 → 필요하면 칸 지정 화면
4. **가져오기 결과 화면** (반영 전 확인)
   - 읽은 항목 수 / 건너뛴 행 수와 이유 / 해석 못 한 값
   - 이전 버전 대비: 추가·삭제·변경된 항목 목록, 항목 수 변화 (예: "TSR 36 → 12 — 양식이 바뀌었을 수 있음" 경고)
   - 문서 안 ID 중복, 형식 오류 목록
5. [반영] 누르면 저장 → 추적성·일정 다시 계산
6. 어떤 단계에서 오류가 나도 앱이 죽지 않고, 오류 내용을 보여 줌

### 문서 ↔ DIA 산출물 연결

- 넣은 파일의 정규화 파일명이 DIA의 정규화 예상 파일명과 같으면 자동 연결 (버전 표기·확장자 무시 → 개정본도 같은 산출물로 연결)
- 같은 게 없으면 비슷한 후보를 보여 주고 사용자가 한 번 고름 → 기억(다음 버전부터 자동)
- 파일명과 문서 종류가 안 맞아 보이면 "확인 필요" 표시

## 7. 연결 해석 (ID 맞추기)

참조 문자열 1개를 아래 순서로 해석합니다 (상세 규칙: FORMATS.md §7).

1. 별칭표에 있으면 그 대상
2. 그대로 일치
3. 정규화 후 일치 (대소문자, `_`/공백/`-` 차이, 앞자리 0 등)
4. **끝 번호 일치**: 같은 종류(TSR 등)의 정의 항목 중 끝 번호가 같은 것. SG 번호가 양쪽에 다 있으면 SG도 같아야 함
   - 후보 1개 → 자동 연결 (표시: "약식 표기")
   - 후보 2개 이상 → **확인 필요** (사람이 ID 대응표에서 고름)
   - 후보 0개 → **없는 ID 참조**

정의 문서 안에서 같은 ID가 여러 번 나오면(ID 중복) 그 ID를 가리키는 참조는 모두 "확인 필요"가 됩니다.

## 8. 상태 정의

### 추적 항목 상태

| 상태 | 조건 | 표시 |
|---|---|---|
| 연결됨 | 다음 단계 항목이 1개 이상 해석됨 | 회색 실선 / 초록 체크 |
| 확인 필요 | 애매한 참조, ID 중복, Yes인데 ID 없음 등 | 노란 점선 / 느낌표 |
| 누락 | 다음 단계가 필요한데 없음 | 주황 점선 끝에 "○○ 없음" |
| 대상 아님 | 다음 단계가 필요 없음 (예: H/W TSR의 SSR, 문서 상태가 미적용/N/A, 타 ECU에 요구하는 FSR) | 회색 글자 |
| 문서 대기 | 다음 단계 문서가 아직 등록 안 됨 | 회색 점선 |

"다음 단계가 필요한지" 규칙:
- FSR(자체, 타 ECU로부터) → TSR 필요. 타 ECU에 요구하는 FSR → TSR 불필요
- TSR → FMEA 근거: 일반(General/공통) 분류는 불필요, 그 외 필요
- TSR(S/W 또는 BOTH) → SSR 필요 / TSR(H/W 또는 BOTH) → HSR 필요
- SSR → SW 시험 필요
- 문서에 미적용·미해당·N/A로 적힌 항목 → 대상 아님(커버리지 계산에서 제외)

### 역방향 확인 (아래에서 위로)

- TSR이 없는 FSR 참조(없는 FSR ID를 가리키는 TSR)
- TSR 연결이 없는 FMEA 고장원인 중 ASIL이 있는 것
- TSR 연결이 없는 SSR 중 ASIL(A~D)이 있는 것

### 산출물(일정) 상태 — 오늘 기준일로 계산

| 상태 | 조건 (위에서부터 먼저 맞는 것) |
|---|---|
| 완료 | 실적 종료일이 있음 |
| 지연 | 계획 종료일 < 오늘, 실적 종료일 없음 |
| 진행 | 계획 시작일 ≤ 오늘, 또는 연결된 문서가 등록됨, 또는 실적 시작일 있음 |
| 미착수 | 그 외 |
| 일정 미기재 | 계획 일정이 비어 있음 (상태와 별개로 경고 표시) |

### Verification Report 작성 여부

- 자동: DIA에 VR 파일명이 있고 그 파일이 등록되면 O. 또는 파일명에 "Verification Report"와 문서 라벨(TSC, FMEA, FTA, DFA, HSI, HSR, HSD, FMEDA 등)이 들어간 파일이 등록되면 해당 산출물 O
- 수동: 화면에서 O/X 직접 변경 가능(자동값보다 우선, 변경 사실 표시)
- **내용은 읽지 않음**
- DIA에서 VR은 별도 줄(예: "TSC VR", "FMEA VR")로 들어오므로 그 자체로 일정·작성 여부를 관리하고, 같은 문서 라벨의 원본 산출물 줄(예: "TSC")에도 "VR 작성" 칸으로 함께 표시
- VR이 아닌 산출물 중 짝이 되는 VR 줄이 없는 것은 "해당 없음"

## 9. 화면

공통 레이아웃: 왼쪽 메뉴(추적성 / 산출물 일정 / ID 대응표 / 문서 관리 / 설정), 위쪽에 프로젝트 이름과 [문서 넣기], [엑셀 출력].

### 9.1 추적성 (탭: 시스템 / 소프트웨어 / 하드웨어)

- **단계 카드**: 각 단계의 개수와 연결률(%) + 진행 막대. 문서가 없으면 점선 카드에 "문서 미등록"
  - 시스템: FSR 수 → TSR 연결 (n/전체 FSR) → FMEA 근거 (n/대상 TSR) → 시스템 통합 시험(자리)
  - 소프트웨어: S/W 할당 TSR 수 → SSR 연결 → SW 요구사항 시험
  - 하드웨어: H/W 할당 TSR 수 → HSR 연결 → FMEDA
- **연결 지도(기본 보기)**: 단계별 열에 항목을 카드로 놓고 선으로 연결
  - 카드: ID + 짧은 제목 + 상태 아이콘. 상태별 테두리·배경색 (색만으로 구분하지 않고 아이콘/글자 병행)
  - 선: 연결됨 회색 실선, 확인 필요 노란 점선, 누락은 주황 점선 끝에 "TSR 없음" 같은 표시
  - 1:N, N:1 연결 모두 표현. ID 중복이면 같은 ID 카드 2개에 점선이 같이 걸리게
  - 시스템 탭은 SG에서 FSR로 갈라지는 모양
  - **양이 많을 때**(TSR 300개 이상인 문서 있음): SG 선택 드롭다운으로 한 SG씩 보기, 문제 있는 항목 먼저, 정상 연결은 "정상 n개" 묶음 카드로 접었다가 클릭하면 펼침. 화면이 느려지지 않게 할 것
  - 카드 클릭 → 그 항목의 위·아래 연결만 강조 + 옆 패널에 상세(출처 문서, 적힌 참조 문자열 원문, 해석 방식)
- **목록 보기(전환 버튼)**: 표 형태, 상태 필터(전체 / 누락 / 확인 필요 / 연결됨)
- 소프트웨어 탭 아래쪽: **역방향 확인** — TSR 연결 없는 안전 관련 SSR
- 하드웨어 탭: HSR·FMEDA 미등록 상태를 점선 빈 자리로 보여 주고 [HSR 넣기] 버튼. FMEDA 목표값(ASIL별 SPFM/LFM/PMHF)은 참고로 표시

### 9.2 산출물 일정

- DIA에서 온 산출물 목록. 구분(관리 / 시스템 / SW / HW — Part 번호로 자동 분류: 2·8부=관리, 3·4부=시스템, 6부=SW, 5부=HW, 그 외=기타) 묶음
- 칸: 산출물(+ 문서 라벨), 담당(팀·사람), 상태, 계획 시작~종료, 실적, D-day, 등록 문서(버전·등록일 또는 "미등록"), VR 작성 O/X
- 간트 막대: 계획 기간 막대 + 오늘 선 + (있으면) 마일스톤 선. 마일스톤은 프로젝트 설정에서 직접 입력
- 필터: 구분, 담당자, 상태. 지연은 눈에 띄게
- 상단 요약: 전체 / 완료 / 진행 / 지연 / 미착수 / 일정 미기재 건수
- 일정·담당은 **DIA가 원본** → 툴에서 수정하지 않음(바꾸려면 DIA를 고쳐서 다시 넣음). VR 작성 O/X만 화면에서 수정 가능

### 9.3 ID 대응표

- 확인 필요 / 없는 ID / 약식 표기로 자동 연결된 참조를 한 표에
- 확인 필요 항목: 후보들을 제목과 함께 보여 주고 선택 → 별칭으로 저장
- 저장된 별칭 목록 보기·삭제

### 9.4 문서 관리

- 등록된 문서 목록(종류, 파일명, 버전, 등록일, 읽은 항목 수, 경고 수, 연결된 DIA 산출물)
- 버전 이력, 각 버전의 가져오기 결과 다시 보기, 삭제

### 9.5 설정

- 칸 이름 동의어 추가
- 처음 보는 양식의 칸 지정(미리보기 표에서 "이 칸 = 내 ID / 위 단계 ID / 제목 / ASIL / 할당" 선택 → 저장해 재사용)
- 프로젝트 마일스톤 입력, 오늘 기준일 덮어쓰기

## 10. 엑셀 출력

파일명: `<프로젝트>_산출물작성리스트_YYYYMMDD.xlsx`

### 시트 1 "작성 리스트"
- 머리말: 프로젝트, 출력일, 요약(전체 / 완료 / 진행 / 지연 / 미착수 / 일정 미기재)
- 표 (DIA 행 순서 유지, 한 DIA 행에 파일이 여러 개면 하위 줄로):

| 칸 | 내용 |
|---|---|
| DIA No. | DIA 행 번호 |
| 구분 | 관리 / 시스템 / SW / HW / 기타 |
| 산출물 | Work product (+ 문서 라벨) |
| 예상 파일명 | DIA의 실제 파일명 줄 |
| 등록 문서 | 등록된 파일명, 버전, 등록일 (없으면 "미등록") |
| 담당 팀 / 담당자 | **모든 담당자 표시**(여러 명이면 모두). 비어 있으면 "담당 미지정" |
| 계획 시작 / 계획 종료 / 실적 시작 / 실적 종료 | 날짜 |
| 상태 | 완료 / 진행 / 지연 / 미착수 (+ 일정 미기재) |
| VR 작성 | O / X / 해당 없음 |
| 비고 | 메모, 날짜 경고 |

- 서식: 상태별 셀 색(완료 초록, 지연 주황, 미등록 회색), 머리글 틀 고정, 자동 필터, 열 너비 자동, 인쇄 시 가로·한 페이지 너비
- 담당이 N/A인 DIA 행은 제외. 담당 주체(당사 / 고객사 / 사내 타 팀) 구분 없이 담당이 적힌 행은 모두 포함

### 시트 2 "담당자별 요약"
- 담당자 | 팀 | 전체 | 완료 | 진행 | 지연 | 미착수 — 지연 많은 순

### 시트 3 "추적성 누락" (출력 시 선택)
- 누락·확인 필요 항목 목록: 단계, 항목 ID, 제목, 문제 종류, 출처 문서

## 11. 비기능 요구

- 오프라인 전용, 외부 요청 0건 (CSP로 원격 로드 차단)
- 큰 워드 파일(본문 XML 약 20MB, 표 300개 이상, 그림·OLE 다수) 가져오기 10초 이내 목표. 그림은 읽지 않음
- 화면 반응: 항목 1,000개 수준에서 탭 전환 1초 이내
- 데이터 저장 실패 시 이전 데이터 보존
- 앱 로그는 로컬 파일에만 (문서 내용은 로그에 쓰지 않음)
- UI는 한국어

## 13. 단계 계획 (마일스톤)

> 각 마일스톤 시작 전에 계획을 사용자에게 보여 주고 확인받은 뒤 진행합니다.

**M0. 골격 + 설치 테스트**
- Electron + React 빈 앱, 왼쪽 메뉴만 있는 화면
- GitHub Actions로 Windows 설치 파일 빌드 → 아티팩트/Release 업로드
- 완료 기준: 회사 PC에서 관리자 권한 없이 설치·실행됨 (사용자가 확인)

**M1. DIA → 산출물 일정 + 엑셀 출력**
- 문서 넣기 공통 흐름(DRM 검사, 종류 판별, 가져오기 결과 화면)
- DIA 읽기(FORMATS.md §6), 산출물 일정 화면, VR 작성 여부(파일명 기준 자동 + 수동)
- 문서 등록 시 DIA 산출물과 파일명 매칭
- 엑셀 출력 시트 1·2
- 완료 기준: 가짜 DIA로 여러 파일이 한 칸에 든 행, 날짜 오류, 담당 여러 명/빈칸/N/A가 모두 의도대로 나옴

**M2. FSR + TSC → 시스템 추적성(목록)**
- FSR 읽기, TSC 읽기, 연결 해석(§7), 상태 계산(§8)
- 추적성 시스템 탭(단계 카드 + 목록 보기), ID 대응표 화면
- 완료 기준: 가짜 FSR/TSC로 ID 중복, 붙은 표, TSR 없는 FSR, 없는 ID 참조가 정확히 잡힘

**M3. 연결 지도**
- 시스템 탭 연결 지도, 카드 클릭 강조·상세 패널, 대량 항목 접기/SG 선택
- 완료 기준: TSR 300개 이상 가짜 TSC에서도 부드럽게 동작

**M4. FMEA + SRS → FMEA 근거, 소프트웨어 탭, 역방향 확인**
- FMEA 읽기, SRS 읽기, 소프트웨어 탭(지도+목록), 역방향 확인, 엑셀 시트 3
- 완료 기준: 약식 TSR 표기(`TSR-017`, `<고객>_<제품>_TSR_017`)가 끝 번호로 연결되고, 후보 여러 개면 확인 필요로 뜸

**M5. 하드웨어 탭 + 처음 보는 양식 대응**
- 하드웨어 탭(HSR·FMEDA 자리), 설정의 칸 지정 기능(HSR, SW 시험 명세 등 새 양식용), 칸 이름 동의어 편집
- 완료 기준: 칸 지정만으로 새 양식 문서가 연결됨
