SPEC·FORMATS와 다르게 하거나, 문서에 없던 것을 정한 내용을 날짜와 함께 남깁니다.

## 2026-11-10 (M0)

- **저장소를 퍼블릭으로 운영** (SPEC §3 "비공개"에서 변경)
  - 이유: GitHub Actions를 시간 제한 없이 쓰기 위해 (사용자 결정)
  - 대책: 고객사·제품·회사 이름과 실제 ID는 자리 표시나 가짜 값으로 바꿈
    (고객사 이름 → `<고객사>`, 예시 ID의 제어기 약어 → `CTL`, DRM 제품명 삭제).
    DRM 판별 글자 `DocuRay`는 판별 코드에 필요해서 남김.
  - 퍼블릭이라 Release 설치 파일은 GitHub 로그인 없이 받을 수 있음
- **push마다 Windows 설치 파일 빌드** (CLAUDE.md "push는 테스트만"에서 변경)
  - push마다: 테스트 → Windows 빌드 → 빌드된 exe 실행 확인(메뉴 표시, 외부 요청 0건, 화면 캡처) → Actions 아티팩트
  - main에 push했을 때 package.json 버전(`v0.0.1` 등)의 Release가 아직 없으면: Actions가 Release와 태그를 만들어 설치 파일을 올림
    (이 작업 공간에서는 태그 push가 HTTP 403으로 막혀 있어서, 태그를 직접 올리는 대신 이렇게 함)
  - 이유: 퍼블릭이라 Actions 시간 제한이 없고, 빌드가 깨진 것을 바로 알 수 있음
- **설치 파일 3종**: NSIS 사용자 단위 설치(Setup.exe) + portable exe + zip
  - zip 추가 이유: portable exe는 실행할 때마다 임시 폴더에 풀어서 실행하는데, 회사 보안 프로그램이 임시 폴더 실행을 막으면 안 될 수 있음. zip은 원하는 폴더에 풀어 바로 실행
- **빌드 도구 electron-vite 사용**: main / preload / renderer 빌드를 한 설정으로 관리 (Vite 기반이라 SPEC의 React + Vite와 같음)
- **폰트 Pretendard(OFL) 포함**: 화면 글꼴을 앱 안에 넣음(외부 요청 0건)
- **외부 요청 차단 두 겹**: 화면의 CSP + 메인 프로세스에서 `file:`·`devtools:`·`data:` 외 모든 요청 취소. Electron 기본 메뉴(홈페이지 링크) 제거, 새 창 열기·페이지 이동 막음
- **맞춤법 사전 숨은 접속 차단**: Electron은 맞춤법 검사를 꺼도 시작할 때 영어 사전을 Google 서버(`redirector.gvt1.com`)에서
  받으려 함. 이 접속은 앱의 요청 차단기에 보이지 않음 → 사전 언어 목록을 비워서(`setSpellCheckerLanguages([])`) 시작하지 않게 함
  - 실행 확인 테스트에 Chromium 네트워크 기록(`--log-net-log`) 검사를 추가: 앱 코드 밖의 숨은 접속까지 0건이어야 통과.
    고치기 전 코드로 돌리면 이 검사가 `redirector.gvt1.com`으로 실패하는 것을 확인함
- **프록시 사용 안 함** (`--no-proxy-server`): Windows에서 Chromium이 "프록시 자동 검색"(WPAD)으로 내부망의
  `wpad` 서버를 찾으려 하는 것을 위 검사가 잡음. 앱은 어떤 서버에도 접속하지 않으므로 프록시 조회 자체를 끔
- **버전**: M0 = `0.0.1`. 마일스톤이 끝나면 package.json 버전을 올려 main에 push → Release 자동 생성

## 2026-11-10 (M1 · M2)

- **M1과 M2를 이어서 진행** (사용자 결정): M1이 끝나면 `v0.1.0` Release를 만들고, 회사 PC 확인을 기다리지 않고 M2(`v0.2.0`)로 넘어감
- **엑셀 읽기 라이브러리: npm의 SheetJS 0.18.5** (SPEC §3의 SheetJS)
  - 최신판은 SheetJS 자체 서버에서만 받을 수 있는데 작업 공간에서 막혀 있어, 사용자 결정으로 npm 판을 씀
  - 이 판에는 조작된 엑셀 파일을 열 때의 알려진 약점 2건(프로토타입 오염, 정규식 지연)이 있음 →
    문서 읽기를 **파일마다 새로 띄우는 별도 작업 스레드**에서 하고, 120초가 넘으면 강제로 끝냄. 앱 본체와 화면에는 영향 없음
- **아직 내용을 읽지 않는 문서도 등록은 받음**: FMEA·SRS(M4), 기타(M5)는 파일만 등록 → 산출물 일정의 "등록 문서"와 DIA 연결에 쓰임
- **DIA는 프로젝트당 1개**: 파일 이름이 달라도 새로 넣은 DIA가 활성, 이전 것은 버전 이력으로 보관
- **일정 미기재 = 계획 시작·종료 중 하나라도 비어 있음** (형식 오류로 못 읽은 날짜 포함)
- **날짜 글자 추가 인정**: `2026/06/05`, 숫자 `20260504`도 날짜로 읽음
- **VR 작성 수동 변경은 VR 줄 기준**: 원본 줄("TSC")의 VR 칸은 짝 VR 줄("TSC VR")의 값을 보여 주고, 어느 쪽에서 바꿔도 VR 줄 값이 바뀜.
  산출물 키(No. + 정규화 파일명) 기준이라 DIA 새 버전에서도 유지
- **문서 ↔ 산출물 연결 기억은 정규화 파일명 기준**: 다음 버전 파일(R1 → R2)도 자동으로 같은 산출물에 연결
- **엑셀 출력 시트 1에 D-day 칸 추가**, DIA No.는 하위 줄에도 반복(필터용)하고 산출물 칸에 `└`로 하위 줄 표시
- **담당자별 요약**: 사람 없이 팀만 적힌 줄은 "(팀 담당)", 둘 다 비면 "담당 미지정"으로 셈
- **프로젝트 파일 형식 `schema: 1`**: 연결·상태는 저장하지 않고 화면에서 매번 계산 (원본 문서가 바뀌면 바로 반영)
- **FSR 시트 고르기**: FSR 헤더가 있는 시트 중 이름에 `(SG…)`나 `요구사항`이 든 시트를 우선 읽고, `Sheet1`·`기타` 같은 작업용 시트는 읽지 않음 (가져오기 결과에 안내)
- **FSR 상태 규칙 보충**: FSR ID가 FSR 문서 안에서 중복이면 "확인 필요". 연결된 TSR이 모두 미적용이어도 "연결됨"으로 두고 이유에 표시
- **TSR의 다음 단계(FMEA 근거)는 M4 전까지 "문서 대기"**: 분류가 일반·공통인 TSR과 Status가 미적용·미해당·N/A인 TSR은 "대상 아님"
- **점 형식 ID(`FSR.001.009`)는 끝 번호 비교를 하지 않음**: `FSR.003.009`가 `FSR.001.009`에 잘못 붙는 것을 막기 위해 (FORMATS §7.3 "전체 정규화 비교 우선")
- **ID 대응표에서 "없는 ID"도 사람이 대상을 골라 별칭으로 저장 가능** (오타·옛 ID 대응용). 메뉴 옆 숫자 = 확인 필요 + 없는 ID (같은 참조는 1건)
- **하드웨어 탭의 FMEDA 목표값 표는 M2에서 미리 표시** (참고용, ISO 26262-5)
- **연결 지도는 M3**: M2의 추적성 화면은 단계 카드 + 목록 보기

## 2026-11-10 (M3)

- **연결 지도가 시스템 탭의 기본 보기**, [목록]으로 표 보기 전환 (SPEC §9.1)
- **지도 배치는 미리 계산해서 그림** (`src/core/traceMap.ts`): 카드 위치를 계산한 뒤 카드(버튼)와 선(SVG)만 그려서,
  TSR 320개를 모두 펼쳐도 Windows에서 0.1초 안팎. 화면 위치를 재지 않아 테스트로 확인 가능
- **정상 연결 묶음 기준**: FSR이 "연결됨"이고, 애매한 참조·ID 중복이 없고, 연결된 TSR에 문제(없는 참조·중복 등)가 하나도 없으면 "정상" →
  SG마다 "정상 FSR n개" / "TSR m개" 묶음 카드로 접음. 정상 FSR에만 연결된 깨끗한 TSR만 묶음에 들어감
- **TSR은 처음 연결된 FSR의 SG 블록에 한 번만** 그림 (여러 SG의 FSR을 가리키면 선이 블록을 넘어감). FSR에 연결이 없으면 TSR ID의 SG 번호로, 그것도 없으면 "SG 미상" 블록
- **SG 하나만 볼 때** 다른 SG 블록에 그려진 TSR로 가는 선은 생략 (상세 패널에는 모두 나옴)
- **카드 강조**: 고른 카드에서 선을 거꾸로 따라 위쪽, 선을 따라 아래쪽만 강조 (형제 카드로는 번지지 않음)
- **FMEA 근거 열은 M4 전까지 점선 자리 카드 하나**

## 2026-11-10 (M4)

- **FMEA 헤더는 "헤더 모양의 글자"로만 판별**: `3. Failure Cause…`, `고장 원인 (FC)`처럼 시작·전체가 맞을 때만 헤더로 봄.
  데이터 칸의 "…고장 원인…" 문장을 헤더로 착각하던 문제를 가짜 문서로 발견해 고침
- **FMEA 고장원인은 ID가 없어서 `시트#행`을 ID로 씀** (예: `FMEA_SG001#12`). 화면에는 "시트 n행"으로 표시
- **FMEA 근거 연결 방향**: 고장원인의 TSR ID 칸 → TSR. TSR(일반·미적용 제외)을 가리키는 고장원인이 하나라도 해석되면 "연결됨", 애매한 참조뿐이면 "확인 필요", 없으면 "누락(FMEA 근거 없음)"
- **TSR 연결 칸이 없는 옛 FMEA만 있으면** FMEA 근거는 "문서 대기(작성 여부만)"로 두고 연결률을 계산하지 않음
- **끝 번호 규칙 그대로 적용**: SG 번호가 없는 TSR(`TSR-CTL-GEN-002`, `TSR-CTL-DOOR-026`)도 후보가 됨 →
  `CUST_CTL_SG002_TSR_002`처럼 끝 번호가 같으면 "확인 필요". 사람이 한 번 고르면 기억
- **SSR 참조는 할당과 관계없이 모든 TSR에서 찾음**: H/W TSR을 가리키는 SSR도 연결로 보여 주고, 소프트웨어 지도에 그 TSR을 회색("S/W 할당 아님") 카드로 표시
- **안전 관련 SSR = Functional Safety Related가 Yes이거나 ASIL A~D**. 안전 무관이고 참조도 없는 SSR은 지도에서 빼고 목록에만
- **SW 요구사항 시험은 M5 전까지 자리** (안전 관련 SSR의 다음 단계 = "문서 대기")
- **소프트웨어 지도 묶음 = TSR ID의 SG 번호** (없으면 "일반·기타"), TSR 연결이 없는 SSR은 "TSR 연결 없음" 묶음
- **별칭은 문서 종류별** (TSC→FSR, FMEA→TSR, SRS→TSR): 같은 글자 `TSR-005`라도 FMEA와 SRS에서 따로 기억. ID 대응표 숫자 = 문서 종류별 같은 참조 1건
- **엑셀 시트 3 "추적성 누락"은 출력할 때 고름** (기본: 포함). 단계: FSR → TSR, TSR → FSR(참조), TSR → FMEA 근거, 역방향: FMEA 고장원인, TSR → SSR, 역방향: SSR

## 2026-11-10 (M5)

- **처음 보는 양식(HSR, SW 시험 명세)은 "칸 지정 규칙"으로 읽음**: 사람이 머리글(워드 키-값 표는 첫 칸의 키) 칸마다 역할
  (내 ID·위 단계 ID·제목·ASIL·할당·상태)을 정하면 규칙으로 저장. 규칙은 프로젝트 설정에 저장되고 설정 화면에서 보거나 지움
- **같은 모양 판단 = 규칙에 쓴 머리글이 모두 있음** (대소문자·띄어쓰기·줄바꿈 무시). 내장 판별이 안 된 문서나,
  사람이 종류를 HSR·SW 시험으로 고른 문서에만 규칙을 씀 → 기존 FSR·TSC·FMEA·SRS 읽기에는 영향 없음
- **파일명에 `HSR`이 있으면 HSR로 보고 [칸 지정]을 안내**, `FMEDA`가 있으면 FMEDA로 파일만 등록 (FMEDA는 양식이 정해지지 않아 작성 여부만, SPEC §8)
- **칸 지정이 안 된 HSR은 반영 기본값이 꺼짐**: 읽은 항목이 없는 채로 반영되는 것을 막음
- **위 단계 ID 칸의 참조 찾기**: 칸에 "TSR"이 있으면 TSR 모양 ID를, 없으면 숫자가 든 낱말을 참조로 봄 (여러 개는 줄바꿈·쉼표·공백으로 나눔)
- **HSR 참조는 할당과 관계없이 모든 TSR에서 찾음** (SSR과 같은 방식). HSR이 필요한 TSR = 할당 H/W 또는 S/W+H/W
- **SW 요구사항 시험 단계**: SW 시험의 검증 요구사항 칸 → SSR. 안전 관련 SSR 중 시험이 하나라도 연결되면 "연결됨"
- **별칭은 HSR→TSR, SW 시험→SSR도 문서 종류별로 따로 기억** (ID 대응표에서 고름)
- **하드웨어·소프트웨어 지도는 같은 그리기 코드** (`buildChainMap`): 위 단계 → 이 단계 → 다음 단계 3열, 묶음·정상 접기·강조 규칙은 M3·M4와 같음
- **동의어 편집**: 설정에서 칸 이름 동의어를 추가하면 기본 동의어에 더해서 씀. 이미 넣은 문서는 그대로이고, **문서를 다시 넣을 때부터** 적용
- **엑셀 시트 3 단계 추가**: SSR → SW 시험, 역방향: SW 시험, TSR → HSR, 역방향: HSR
- **알림(토스트)은 최대 3개까지만 쌓음** (넘치면 오래된 성공 알림부터 지움, 오류 알림은 남김). 연속 작업 후 알림 8개가 화면 오른쪽 절반을 6초간 가리던 문제
- **실행 확인의 "카드 누르기 1초 이내"는 앱 반응 시간으로 잼**: 화면이 클릭을 받은 순간 → 상세 패널이 그려진 다음 프레임까지.
  Playwright 클릭 동작 전체 시간(스크롤·가림 대기 포함)과 누르기 전에 카드를 가린 것은 결과에 함께 남김
  (Windows CI에서 한 번 3.5초가 나왔는데, 같은 코드가 로컬에서 70ms였고 앱 쪽 계산은 바뀐 것이 없었음)

## 2026-11-10 (업데이트 기능 — 사용자 결정)

- **"외부 네트워크 요청 0건" 규칙에 업데이트만 예외**: 사용자가 "설정에 버전 확인 → 업데이트, 앱을 켤 때 자동 확인"을 골랐음
  (다른 안: 브라우저로 Release 페이지만 열기 / 누를 때만 확인). CLAUDE.md·SPEC §2 표 문구를 함께 고침
- **업데이트 전용 연결(세션)만 접속**: 화면(CSP)과 기본 세션의 요청 차단기는 그대로 모두 막음. 업데이트 세션은
  `api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`의 https만 허용.
  받을 파일 주소는 이 저장소의 `releases/download/`만. 보내는 것은 User-Agent의 앱 버전뿐
- **업데이트 세션만 Windows 프록시 설정을 따름** (회사망). 앱 전체의 `--no-proxy-server`(WPAD 방지)는 그대로 두고,
  세션별 `setProxy({ mode: 'system' })`가 이를 덮어쓰는 것을 실험으로 확인함
- **세션마다 맞춤법 사전을 따로 받으려 함** → 업데이트 세션도 사전 목록을 비움 (실행 확인의 Chromium 네트워크 기록 검사가 잡아냄)
- **electron-updater를 쓰지 않고 직접 구현**: Release의 `SHA256SUMS.txt`(이미 CI가 만듦)와 받은 파일의 확인값이 맞을 때만 씀.
  코드 서명이 없어서 서명 확인은 못 함 → 확인값은 "깨진·바뀐 파일"을 막는 용도
- **설치형**: `%TEMP%\FuSaTrace-update`에 받고, [지금 설치하고 다시 시작]을 누르면 설치 직전에 확인값을 한 번 더 보고
  설치 프로그램을 `--updated /S --force-run`으로 실행한 뒤 앱을 닫음 → 조용히 덮어 설치하고 앱을 다시 켬.
  받기와 설치를 두 단계로 나눔 (작업 중 갑자기 앱이 닫히지 않게)
- **포터블·압축본**: 실행 중인 파일을 바꿀 수 없어서 다운로드 폴더에 새 파일만 받아 둠
- **자동 확인**: 창이 뜨고 3초 뒤 1번. 앱 전체 설정 `%APPDATA%\FuSaTrace\app-config.json`(프로젝트와 별개)에서 끌 수 있음.
  자동 확인이 실패해도 알림을 띄우지 않고 설정 화면에만 이유를 보여 줌
- **새 버전 판단**: 태그 `v<숫자>.<숫자>.<숫자>`만, 숫자로 비교. 모양이 다른 태그는 새 버전으로 보지 않음
- **실행 확인 테스트는 가짜 GitHub(127.0.0.1)로**: `FUSA_UPDATE_API`는 내 PC의 http 주소만 받아들임(그 외 값은 무시).
  Windows CI에서는 실제 Setup.exe를 설치한 뒤 앱에서 업데이트 → 덮어 설치 → 앱이 다시 켜지는 것까지 확인
- **설치 폴더는 `%LOCALAPPDATA%\Programs\fusa-trace`**: electron-builder의 사용자 단위 원클릭 설치는 제품 이름이 아니라 패키지 이름 폴더를 씀
  (업데이트 설치 확인 테스트로 발견, README의 "FuSa Trace" 폴더 안내를 고침). 제거 프로그램 이름은 `Uninstall FuSa Trace.exe`
