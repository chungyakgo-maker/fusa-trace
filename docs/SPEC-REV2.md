# SPEC 개정안 2 — 추적성 연결성·정합성 검사 도구

> 기준: v0.6.0 (M0~M5 완료). 이 문서는 `docs/SPEC.md`에 **더하거나 바꾸는 것**만 적습니다.
> 저장소가 퍼블릭이므로 고객사·제품·회사 이름, 실제 ID·파일명은 쓰지 않고 자리 표시(CUST, CTL)만 씁니다.
> ISO 26262 원문은 저장소에 넣지 않습니다. 조항 번호(2018판)만 인용하고 내용은 요약합니다.

---

## 1. 바뀌는 정체성

### 한 줄 정의
> **기능안전 제출 문서를 넣으면, 리뷰 전에 고쳐야 할 추적성·정합성 문제를 알려 주는 검사기.** 입력도 관리도 하지 않는다.

### 왜 필요한가 (사용자 확인 사항)
- 문서(TSC, SRS, FMEA 등)는 ALM(코드비머)과 **따로 작성**한다 → 문서끼리, 문서와 ALM이 어긋날 수 있다
- 고객 리뷰는 **제출 문서**로 받는다 → ALM이 맞아도 문서가 틀리면 지적된다
- 엑셀(DIA·문서)과 ALM은 각자의 원본이다. 이 툴은 **세 번째 원본이 되지 않는다**

### 원칙
1. 데이터 입력 없음. 문서를 넣으면 검사 결과가 나온다
2. 툴이 요구사항을 만들거나 고치지 않는다 (FSR → TSR 자동 생성 없음)
3. 같은 문서를 넣으면 항상 같은 결과 (규칙 기반, AI 판단 없음, 외부 통신 없음)
4. 모든 지적에 **어디를 고칠지**(문서·항목·위치)와 **근거 조항**을 붙인다

### 범위에서 빼는 것
- Verification Report(동료검토) 체크리스트 내용 → 계속 **작성 여부만**
- 문장 품질 검사(모호한 표현 등)
- 관리용 기능(홈 대시보드, 독촉 문안 등)은 만들지 않음. 산출물 일정·작성 리스트는 지금 기능을 유지하되 보조 메뉴로

## 2. 검사 규칙

### 2.1 공통
- 심각도: **오류**(제출 전 반드시 수정) / **경고**(확인 필요) / **참고**(문서 대기 등)
- 문서·항목 상태가 "대상 아님"(미적용·미해당·N/A)인 항목은 검사하지 않음
- 아래 단계 문서가 **아직 등록되지 않았으면** 그 단계 규칙은 항목마다 지적하지 않고, 프로젝트당 참고 1건만 냄
  - 예: "SRS 미등록 — SSR 연결 검사 생략"
- 지적 하나 = 규칙 ID + 대상 항목 + 관련 항목 + 내용 + 고칠 문서 + 위치 + 근거 조항

### 2.2 연결성 규칙 (C)

| ID | 규칙 | 심각도 | 고칠 문서 | 근거 (ISO 26262:2018) |
|---|---|---|---|---|
| C-01 | **ID 중복**: 정의 문서 안에 같은 ID가 다른 내용으로 2번 이상 | 오류 | 정의 문서 | Part 8 Clause 6 (요구사항 고유 식별) |
| C-02 | **없는 ID 참조**: 참조가 어떤 정의 항목과도 맞지 않음 | 오류 | 참조하는 문서 | Part 8 Clause 6 (추적성) |
| C-03 | **애매한 약식 표기**: 끝 번호로 맞췄더니 후보가 2개 이상 | 경고 | 참조하는 문서 | Part 8 Clause 6 |
| C-04 | **TSR이 없는 FSR** (자체 FSR, 타 ECU로부터 받은 FSR 대상. 타 ECU에 요구하는 FSR은 제외) | 오류 | TSC | Part 4 Clause 6, Part 8 Clause 6 |
| C-05 | **SSR이 없는 S/W TSR** (할당 SW 또는 BOTH, SRS 등록 시) | 오류 | SRS | Part 6 Clause 6 |
| C-06 | **FMEA 근거가 없는 TSR** (분류가 일반·공통인 TSR 제외. FMEA에 TSR ID 칸이 없으면 검사 생략 + 참고 1건) | 경고 | FMEA | Part 9 Clause 8 |
| C-07 | **TSR 연결이 없는 안전 관련 SSR** (ASIL A~D, 또는 Functional Safety Related가 Yes) | 경고 | SRS | Part 6 Clause 6, Part 8 Clause 6 |
| C-08 | **TSR 연결이 없는 FMEA 고장원인** (ASIL A~D인 행) | 경고 | FMEA | Part 9 Clause 8 |
| C-09 | **"Yes"인데 TSR ID 없음** (SRS Functional Safety Related) | 경고 | SRS | Part 8 Clause 6 |
| C-10 | **시험이 없는 SSR** (SW 요구사항 시험 명세 등록 시) | 경고 | SW 시험 명세 | Part 6 Clause 11 |

### 2.3 정합성 규칙 (K) — 연결된 위·아래 항목끼리 비교

적용 연결: SG → FSR, FSR → TSR, TSR → SSR, TSR → HSR (해당 값이 양쪽에 있을 때만)

| ID | 규칙 | 심각도 | 고칠 문서 | 근거 |
|---|---|---|---|---|
| K-01 | **ASIL 하향**: 하위 ASIL이 상위보다 낮음 | 오류 | 하위 문서 | Part 3 Clause 7, Part 4 Clause 6, Part 8 Clause 6 |
| K-02 | **FTTI 초과**: 하위 FTTI가 상위 FTTI보다 김 | 오류 | 하위 문서 | Part 1(FTTI 정의), Part 4 Clause 6 |
| K-03 | **Safe State 불일치**: 하위 Safe State가 상위에 정의된 값 밖이거나 Safe State 형식이 아님 | 경고 | 하위 문서 | Part 4 Clause 6 |
| K-04 | **할당과 하위 문서 불일치**: H/W 또는 BOTH인데 HSR 없음(HSR 등록 시) / Allocation이 비었거나 해석 불가 | 경고 (빈칸·해석 불가는 오류) | HSR / TSC | Part 4 Clause 6, Part 5 Clause 6 |
| K-05 | **분해 표기인데 DFA 없음**: 어떤 항목이든 ASIL 분해 표기(예: `B(D)`)가 있는데 DFA 산출물이 미등록 | 경고 | DFA (산출물) | Part 9 Clause 5, Part 9 Clause 7 |
| K-06 | **참조 버전 불일치**: TSC가 참조한 FSR 버전 ≠ 최신 등록 FSR 버전 / SRS가 참조한 TSC 버전 ≠ 최신 등록 TSC 버전 | 경고 (참조 버전 미기재는 참고) | 참조하는 문서 | Part 8 Clause 7, Part 8 Clause 8 |

C-05와 K-04가 같은 내용을 두 번 지적하지 않도록, S/W 쪽은 C-05만, H/W 쪽은 K-04만 냅니다.

### 2.4 규칙별 세부 판단

**K-01 ASIL**
- 순서: QM < A < B < C < D
- 값 정리: `B`, `ASIL B`, `ASIL-B` → B / `B(D)` → 분해 표기 (본 등급 B, 원래 등급 D)
- 상위가 여러 개면 가장 높은 상위 등급과 비교
- 하위가 분해 표기 `X(Y)`이면: Y ≥ 상위 등급이면 통과(대신 K-05 대상), 아니면 오류
- 하위 값이 비었거나 `-`면 K-01은 건너뛰고 참고 "ASIL 미기재"

**K-02 FTTI**
- 읽을 값 예: `500ms`, `500 ms`, `2500ms`, `100`, `FTTI: 100ms`
- `500ms / 250ms`처럼 여러 값 → 가장 큰 값으로 비교
- `-`, `N/A`, `T.B.D.` → 건너뜀 (`T.B.D.`는 참고 "FTTI 미정")
- 상위가 여러 개면 가장 짧은 상위 FTTI와 비교
- 상위 FTTI는 FSR 값이 없으면 SG의 FTTI 사용

**K-03 Safe State**
- ID 추출: `SS001`, `SS_001`, `SS-001`, `<코드>SS101` 등 → 같은 형태로 정규화
- 하위 값에 SS ID가 하나도 없고 `N/A`·`-`도 아니면 (예: `Normal Mode`, `S N/A`) → "Safe State 형식 아님" 경고
- 하위 SS ID가 상위 FSR(없으면 SG)의 SS ID 집합에 없으면 → 경고
- 상위가 `-`이거나 미정이면 건너뜀

**K-05 DFA**
- 다음 중 하나라도 있으면 "DFA 등록됨"
  - DIA에서 DFA 라벨 또는 Dependent failures 산출물에 연결된 문서
  - 등록 문서 파일명에 `DFA` 토큰
- 분해 표기가 있지만 상태가 "대상 아님"인 항목뿐이면 검사하지 않음

**K-06 참조 버전**
- TSC에서 읽기: `상위문서` 표의 문서번호 칸, 참조 문서 표의 FSR 파일명·버전 → 버전 토큰(`R2.0`, `R00`, `V1.5`, `v1.5`) 추출
- SRS에서 읽기: 참조 문서 표의 `Baseline Version` 칸 중 TSC(또는 System Requirement) 행
- FSR 최신 버전: 개정이력 마지막 버전, 없으면 파일명의 버전 토큰
- 버전 비교 전 정리: `R2.0` = `R2` = `2.0`, `R00` = `R0` = `0`, 대소문자 무시
- 참조 칸이 `TBD`이거나 비어 있으면 → 참고 "참조 버전 미기재"

## 3. 문서 읽기 추가 사항 (FORMATS.md에 반영)

| 문서 | 추가로 읽을 것 |
|---|---|
| FSR | 각 FSR의 FTTI·Safe State·ASIL·Allocation (이미 읽는 값이면 검사에서 쓰도록 노출). SG별 FTTI·Safe State(안전목표 시트 요약표). 개정이력 최신 버전 |
| TSC | 각 TSR의 ASIL·FTTI(`FTTI / FTHI` 포함)·Safe State·Allocation·분류·Status. `상위문서` 표와 참조 문서 표에서 FSR 버전 |
| SRS | ASIL·FTTI(`FRTI` 오타 포함)·Safety State. 참조 문서 표의 문서 이름·`Baseline Version` |
| FMEA | 고장원인 행의 ASIL |
| 공통 | **모든 항목에 위치 정보 보존**: 엑셀은 시트 이름 + 행 번호, 워드는 "n번째 TSR 표" + 가장 가까운 제목 글자 |

## 4. 화면 변경

### 4.1 메뉴 순서
**검사 결과(기본 화면)** → 추적성 → ID 대응표 → 문서 관리 → 산출물 일정 → 설정

### 4.2 검사 결과 화면
- 맨 위: 오류 / 경고 / 참고 건수 카드 + **"이전 검사 대비: 해결 n건, 새로 생김 m건"**
- 문서별 지적 건수 막대 (어느 문서를 먼저 고칠지)
- 지적 목록 표: 심각도, 규칙 ID·이름, 고칠 문서, 항목 ID, 관련 항목, 내용, 위치, 근거 조항
  - 필터: 심각도, 규칙, 문서
  - 내용 예: "TSR-CTL-SG001-0AA의 FTTI 500ms가 상위 FSR-CUST-0BB의 FTTI 100ms보다 김"
- 지적을 누르면 추적성 지도에서 해당 항목과 관련 항목이 강조되어 근거를 바로 확인
- 문서를 넣을 때마다 자동으로 다시 검사

### 4.3 예외 처리 (최소한의 관리 요소)
- 지적에 [예외 처리] → **사유 필수** 입력 → 목록에서 숨김(필터로 다시 볼 수 있음)
- 예외는 지적의 지문(규칙 ID + 항목 ID + 관련 항목 ID)으로 기억. 다음 검사에서도 같은 지적이면 유지, 사라지면 자동 정리
- 예외 처리된 지적은 리포트의 별도 시트에 사유와 함께 **항상** 나옴 (숨긴 사실이 투명하게 보이도록)

### 4.4 검사 이력
- 검사할 때마다 지적 지문 목록과 건수만 저장 (문서 내용은 저장하지 않음)
- "해결/새로 생김" 계산과 리포트 요약에만 사용

## 5. 검사 리포트 엑셀 (핵심 출력)

파일명: `<프로젝트>_검사리포트_YYYYMMDD_HHMM.xlsx`

| 시트 | 내용 |
|---|---|
| 1. 요약 | 프로젝트, 검사 일시, 앱 버전, **검사에 쓴 문서 목록**(종류·파일명·버전·등록일), 심각도별·규칙별·문서별 건수, 이전 검사 대비 해결/새로 생김 |
| 2. 지적 목록 | No, 심각도, 규칙 ID, 규칙 이름, 고칠 문서, 항목 ID, 관련 항목, 내용, 위치, 근거 조항, **조치**(빈칸 — 작성자가 채움). 정렬: 심각도 → 고칠 문서 → 항목 ID |
| 3. 예외 처리 | 예외로 둔 지적, 사유, 처리 일시 |
| 4. 추적 매트릭스 | SG / FSR / TSR / FMEA 근거 / SSR / 시험 / HSR 한 줄씩 + 각 칸의 연결 상태 (리뷰어 확인용) |
| 5. TSR 작성 대상 (선택, M9) | §7 참고 |

- 서식: 심각도 색(오류 주황, 경고 노랑, 참고 회색) + 글자 병기, 머리글 틀 고정, 자동 필터, 열 너비 자동, 가로 인쇄
- 기존 "산출물 작성 리스트" 출력은 그대로 유지 (보조 출력)

## 6. 테스트용 가짜 문서 추가 (FORMATS.md §9에 추가)

규칙마다 **걸려야 하는 경우와 걸리면 안 되는 경우**를 최소 1개씩 넣습니다.

- C-04: 타 ECU에 요구하는 FSR(제외되어야 함), 상태가 "대상 아님"인 FSR(제외)
- C-06: 일반 분류 TSR(제외), TSR ID 칸이 없는 FMEA(검사 생략 + 참고 1건)
- K-01: 상위 B → 하위 A(오류), 상위 D → 하위 `B(D)`(통과 + K-05), 상위 D → 하위 `B(C)`(오류), 상위 여러 개
- K-02: `500ms` vs `100ms`(오류), `500ms / 250ms`, `100`(단위 없음), `T.B.D.`(참고), FSR 값 없음 → SG 값 사용
- K-03: `Normal Mode`, `S N/A`(형식 아님), `SS_001` vs `SS001`(같음), 상위에 없는 SS ID
- K-04: Allocation 빈칸, 괄호 오타 `S/W (CUST))`
- K-05: 분해 표기 + DFA 미등록(경고), 분해 표기 + DIA의 DFA 산출물 등록(통과)
- K-06: TSC 상위문서 `TBD`(참고), `R1.9` vs 최신 `R2.0`(경고), SRS `Baseline Version` 불일치
- 예외 처리: 다음 버전 문서에서도 같은 지적 → 유지 / 고쳐져서 사라짐 → 자동 정리
- 검사 이력: R1 → R2로 바꿨을 때 해결·새로 생김 건수가 정확함

## 7. (선택) TSR 작성 대상 목록

- 툴은 TSR 내용을 쓰지 않습니다. **TSR이 지켜야 할 조건만** 정리합니다
- 대상: C-04(TSR이 없는 FSR)
- 칸: FSR ID, FSR 내용(원문 그대로), SG, 상속 ASIL, FTTI 상한, Safe State, Allocation, 출처 위치
- 출력: 검사 리포트 시트 5 또는 별도 엑셀
- 목적: 값을 옮겨 적다 생기는 ASIL·FTTI·Safe State 오기 예방
